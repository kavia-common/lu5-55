DeltaAPI.txt
===========

Purpose
-------
This file captures a proposed "p5-style" API surface for lu5.

- It is intended as a planning/delta document (not a guarantee of implementation).
- It is organized using the same module/category language used by the documentation site
  (`docs/latest/modules.json`), plus additional p5-style modules that are common in p5.js.
- Each entry is marked as:
  - [EXISTS]   : present in current lu5 docs (docs/latest/modules.json)
  - [PROPOSED] : planned / desired API addition
  - [PARTIAL]  : exists in some form, but incomplete or missing common p5 behaviors

Conventions
-----------
For each symbol:

- Name:
- Signature:
- Category/Module:
- Status: [EXISTS] | [PROPOSED] | [PARTIAL]
- Description:
- Parameters:
- Returns:
- Notes:

----------------------------------------------------------------------
BASE / SKETCH LIFECYCLE
----------------------------------------------------------------------

1) Name: setup
   Signature: setup()
   Category/Module: lifecycle
   Status: [PROPOSED]
   Description: Called once before draw loop starts. Initialize sketch state here.
   Parameters:
     - (none)
   Returns:
     - nil - no return value
   Notes:
     - lu5 already supports `function setup()` in examples; documenting it here as part of API surface.

2) Name: draw
   Signature: draw()
   Category/Module: lifecycle
   Status: [PROPOSED]
   Description: Called repeatedly once per frame while looping is enabled.
   Parameters:
     - (none)
   Returns:
     - nil - no return value
   Notes:
     - lu5 already supports `function draw()` in examples; documenting it here as part of API surface.

3) Name: preload
   Signature: preload()
   Category/Module: lifecycle
   Status: [PROPOSED]
   Description: Called once before setup. Intended for synchronous asset loading.
   Parameters:
     - (none)
   Returns:
     - nil - no return value
   Notes:
     - In p5.js, preload ensures assets are ready before setup. lu5 currently has loadImage/loadFont;
       adding preload as a convention would improve parity.

WINDOW / RUNTIME CONTROL
----------------------------------------------------------------------

1) Name: createWindow
   Signature: createWindow(width, height, opts?)
   Category/Module: window
   Status: [EXISTS]
   Description: Create the main window and graphics context.
   Parameters:
     - width: number - window width in pixels
     - height: number - window height in pixels
     - opts?: table - optional settings (title, resizable, vsync, etc.)
   Returns:
     - nil - no return value
   Notes:
     - opts is proposed as a richer p5-style extension (currently likely only width/height).

2) Name: width
   Signature: width
   Category/Module: window
   Status: [EXISTS]
   Description: Current window width in pixels.
   Parameters:
     - (none)
   Returns:
     - number - width in pixels
   Notes:
     - Typically exposed as a global number (not a function).

3) Name: height
   Signature: height
   Category/Module: window
   Status: [EXISTS]
   Description: Current window height in pixels.
   Parameters:
     - (none)
   Returns:
     - number - height in pixels
   Notes:
     - Typically exposed as a global number (not a function).

4) Name: frameRate
   Signature: frameRate(fps?)
   Category/Module: window
   Status: [EXISTS]
   Description: Set (or get) the target framerate.
   Parameters:
     - fps?: number - desired frames per second
   Returns:
     - number|nil - if called without args, returns current target fps (proposed)
   Notes:
     - Returning current fps when no args is proposed for p5 parity.

5) Name: deltaTime
   Signature: deltaTime
   Category/Module: window
   Status: [EXISTS]
   Description: Elapsed time in milliseconds since last frame.
   Parameters:
     - (none)
   Returns:
     - number - milliseconds
   Notes:
     - Typically exposed as a global number (not a function).

6) Name: windowResized
   Signature: windowResized()
   Category/Module: window
   Status: [EXISTS]
   Description: Event callback fired when window is resized.
   Parameters:
     - (none)
   Returns:
     - nil
   Notes:
     - p5 has windowResized callback. lu5 docs include it.

7) Name: loop
   Signature: loop()
   Category/Module: window
   Status: [PROPOSED]
   Description: Resume calling draw() in a loop.
   Parameters:
     - (none)
   Returns:
     - nil
   Notes:
     - Present in some versions of lu5 docs historically; not in docs/latest/modules.json.

8) Name: noLoop
   Signature: noLoop()
   Category/Module: window
   Status: [PROPOSED]
   Description: Stop calling draw() repeatedly; draw can still be invoked manually (see redraw()).
   Parameters:
     - (none)
   Returns:
     - nil

9) Name: redraw
   Signature: redraw(n?)
   Category/Module: window
   Status: [PROPOSED]

   Parameters:

   Returns:
     - nil

10) Name: saveWindow
    Signature: saveWindow(path?)
    Category/Module: window
    Status: [PROPOSED]
    Description: Save a screenshot of the current frame.
    Parameters:
      - path?: string - destination path (default: timestamp-based filename)
    Returns:
      - string|nil - saved path (proposed)
    Notes:
